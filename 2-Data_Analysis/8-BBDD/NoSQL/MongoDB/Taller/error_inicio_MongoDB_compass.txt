The error `ECONNREFUSED 127.0.0.1:27017` and `ECONNREFUSED ::1:27017` means Compass could not open a network connection to MongoDB on your local machine. This is **not an authentication error** yet — Compass is failing before it gets far enough to try username/password.

Because your connection string is:

```text
mongodb://localhost:27017/
```

the most likely causes are:

- MongoDB Server is not running locally
- MongoDB is running on a different port
- `localhost` is resolving to IPv6 (`::1`) and your server is only listening on IPv4
- the server is configured with a `bindIp` setting that does not allow local connections
- a local firewall or security tool is blocking port `27017`

Here is a clear debugging path in MongoDB Compass:

1. Check whether MongoDB Server is actually running

   Compass can only connect if a `mongod` process is listening on the address and port you specified.

   - If you installed MongoDB Server locally, confirm the service is running.
   - On many systems, the default port is `27017`, but MongoDB may be configured to use another port.
   - If MongoDB is stopped, start it and try again in Compass.

2. Verify the host and port in Compass

   Since your URI uses `localhost:27017`, make sure that is really where MongoDB is listening.

   Try these common variants:

   - `mongodb://127.0.0.1:27017/`
   - `mongodb://localhost:<your_actual_port>/`

   If `127.0.0.1` works but `localhost` does not, the issue is usually name resolution, often IPv6-related.

3. Check for the IPv6 `localhost` issue

   Your error includes both:

   - `127.0.0.1:27017`
   - `::1:27017`

   That means Compass tried IPv4 and IPv6, but both were refused. Still, if your server only listens on IPv4, using `127.0.0.1` directly is often the quickest test.

   In Compass, change the hostname from:

   - `localhost` to `127.0.0.1`

   If that connects, keep using `127.0.0.1` or update your server to listen on the appropriate interfaces.

4. Check the MongoDB server `bindIp` configuration

   If MongoDB was recently installed or reconfigured, it may only be listening on a limited interface.

   In the server configuration file, verify the `net.bindIp` setting allows local connections.

   Typical cases:

   - `127.0.0.1` allows IPv4 localhost connections
   - `localhost` may depend on how the OS resolves it
   - if you need both IPv4 and IPv6 localhost support, the server must be configured accordingly

5. Confirm the port is correct

   The default MongoDB port is `27017`, but it can be changed.

   If MongoDB is listening on another port, update the Compass connection string to match it.

6. Check whether something else is using or blocking the port

   If MongoDB is supposed to be running on `27017` but Compass still gets refused, make sure:

   - no firewall is blocking local traffic
   - no security software is interfering
   - no other process is conflicting with the port
   - MongoDB is not crashing during startup

7. If this is a fresh install, start MongoDB before connecting

   A very common situation is that Compass is opened before the database server is running.

   The sequence should be:

   - start MongoDB Server
   - verify it is listening on `127.0.0.1:27017` or your chosen port
   - then connect from Compass

8. About authentication

   Since your URI does not include credentials, Compass is using the default connection behavior, but authentication is **not** the cause of this specific error.

   If authentication were the problem, you would typically see a different error after the server connection succeeds. Right now the server itself is unreachable.

A practical quick test order:

- try `mongodb://127.0.0.1:27017/` instead of `localhost`
- confirm MongoDB Server is running
- confirm MongoDB is listening on port `27017`
- check `net.bindIp`
- retry in Compass

If you want the shortest likely fix: **use `127.0.0.1` instead of `localhost`, and make sure `mongod` is running on port `27017`**.
